# LLM 토큰 선택 파이프라인 가이드

## 1. 개요: LLM은 어떻게 다음 토큰을 고르는가

LLM(Large Language Model)은 **autoregressive** 방식으로 텍스트를 생성한다. 즉, 이전까지 생성된 모든 토큰을 입력으로 받아 **다음 하나의 토큰**을 예측하고, 이를 반복한다.

```
입력: "오늘 날씨가"
  → 모델 → 다음 토큰 후보별 점수(logits) 출력
  → 샘플링 파이프라인 → "좋다" 선택
  → 입력 업데이트: "오늘 날씨가 좋다"
  → 모델 → ... (반복)
```

이 과정에서 핵심 질문은 **"logits로부터 어떤 토큰을 최종 선택할 것인가?"** 이다. 이 문서는 그 선택 과정 전체를 다룬다.

---

## 2. Logits에서 확률 분포로: Softmax

### Logit이란

모델의 마지막 linear layer 출력값이다. 어휘(vocabulary)의 각 토큰에 대한 **비정규화(unnormalized) 점수**로, 양수/음수 모두 가능하며 합이 1이 아니다.

- 어휘 크기가 32,000이면, logit 벡터는 32,000차원
- 값이 클수록 모델이 해당 토큰을 "선호"한다는 의미

### Softmax 변환

Logits를 확률 분포로 변환하기 위해 softmax 함수를 적용한다:

```
P(x_i) = exp(z_i) / SUM_j(exp(z_j))
```

- `z_i`: 토큰 i의 logit 값
- 결과: 모든 값이 0~1 사이, 합이 정확히 1

### 수치 예시

다음 5개 토큰의 logits가 주어졌다고 하자:

| 토큰 | Logit (z) | exp(z) | Softmax P(x) |
|------|-----------|--------|---------------|
| 고양이 | 3.0 | 20.09 | 0.494 |
| 강아지 | 2.0 | 7.39 | 0.182 |
| 토끼 | 1.5 | 4.48 | 0.110 |
| 사자 | 1.0 | 2.72 | 0.067 |
| 쥐 | 0.5 | 1.65 | 0.041 |
| 기타 (3만여개) | ... | ... | 0.106 (합산) |

> 실제로는 3만~15만개 토큰 전체에 대해 계산되며, 대부분의 토큰은 극히 낮은 확률을 갖는다.

## 3. 토큰 선택 파이프라인

모델이 출력한 raw logits는 여러 단계의 변환을 거쳐 최종 토큰 선택에 도달한다. 아래는 대표적인 처리 순서이다 (구현체마다 순서가 약간 다를 수 있음).

```
Raw Logits
    |
    v
[Step 1] Repetition Penalty  -- 이미 나온 토큰의 logit 조정
    |
    v
[Step 2] Temperature Scaling  -- 분포의 날카로움/평탄함 제어
    |
    v
        Softmax 적용 → 확률 분포로 변환
    |
    v
[Step 3] Top-K Filtering      -- 상위 K개 토큰만 남김
    |
    v
[Step 4] Top-P Filtering      -- 누적 확률 p까지만 남김
    |
    v
[Step 5] Min-P Filtering      -- 최대 확률 대비 비율 이하 제거
    |
    v
[Step 6] 재정규화(Renormalization) → 최종 Sampling
```

> **주의**: Temperature와 Repetition Penalty는 **softmax 이전**(logit 공간)에서 적용되고, Top-K/Top-P/Min-P는 **softmax 이후**(확률 공간)에서 적용된다. 이 구분이 중요하다.

이하 모든 예시는 위의 5개 토큰(고양이, 강아지, 토끼, 사자, 쥐)을 연속으로 추적한다.

---

### Step 0: Raw Logits

모델 출력 (기타 토큰 생략, 주요 5개만 추적):

| 토큰 | Raw Logit |
|------|-----------|
| 고양이 | 3.0 |
| 강아지 | 2.0 |
| 토끼 | 1.5 |
| 사자 | 1.0 |
| 쥐 | 0.5 |

---

### Step 1: Repetition Penalty

#### 왜 필요한가

LLM은 이전에 생성한 토큰을 반복하는 경향이 있다. 특히 Open LLM에서 "The cat sat on the mat. The cat sat on the mat. The cat sat on the..."처럼 무한 반복이 발생하는 경우가 흔하다. Repetition penalty는 이미 등장한 토큰의 점수를 낮춰 이를 방지한다.

#### 동작 메커니즘

이전에 생성된 토큰 집합을 `G`라 하면:

```
z_i' = z_i / penalty    (z_i > 0 일 때)
z_i' = z_i * penalty    (z_i < 0 일 때)
```

- `penalty > 1.0`: 양수 logit은 줄이고, 음수 logit은 더 음수로 만듦 → 재등장 확률 감소
- `penalty = 1.0`: 변화 없음

#### 수치 예시 (penalty = 1.2, "고양이"가 이미 생성됨)

| 토큰 | Raw Logit | 기출현 여부 | 조정 후 Logit |
|------|-----------|------------|---------------|
| 고양이 | 3.0 | O | 3.0 / 1.2 = **2.5** |
| 강아지 | 2.0 | X | 2.0 |
| 토끼 | 1.5 | X | 1.5 |
| 사자 | 1.0 | X | 1.0 |
| 쥐 | 0.5 | X | 0.5 |

"고양이"의 logit이 3.0 → 2.5로 감소했다. softmax를 거치면 확률이 줄어들게 된다.

#### OpenAI API의 반복 억제: frequency_penalty & presence_penalty

OpenAI는 repetition_penalty 대신 다른 방식을 사용한다:

```
z_i' = z_i - frequency_penalty * count(i) - presence_penalty * 1(i in G)
```

- **frequency_penalty** (-2.0 ~ 2.0): 해당 토큰이 등장한 **횟수에 비례**하여 logit 감소. 많이 반복된 토큰일수록 강하게 억제
- **presence_penalty** (-2.0 ~ 2.0): 해당 토큰이 **한 번이라도** 등장했으면 고정값만큼 logit 감소. 횟수 무관, 등장 여부만 봄
- 둘 다 0이면 억제 없음

| 방식 | 사용처 | 특징 |
|------|--------|------|
| repetition_penalty (곱셈) | vLLM, TGI, llama.cpp | 구현이 단순, 효과가 직관적 |
| frequency + presence penalty (덧셈) | OpenAI API, vLLM(호환) | 더 세밀한 제어 가능 |

---

### Step 2: Temperature Scaling

#### 왜 필요한가

Softmax를 직접 적용하면, 모델의 확신도(confidence)가 그대로 반영된다. 하지만 우리는 상황에 따라 **더 확신있게(sharp)** 또는 **더 다양하게(flat)** 생성하고 싶을 때가 있다. Temperature는 이 "확신도의 강도"를 조절하는 다이얼이다.

#### 동작 메커니즘

Softmax 적용 **전에** logits를 temperature T로 나눈다:

```
z_i' = z_i / T
```

그 후 softmax를 적용:

```
P(x_i) = exp(z_i / T) / SUM_j(exp(z_j / T))
```

- **T = 1.0**: 변화 없음 (기본값)
- **T < 1.0**: logit 차이가 증폭 → 분포가 sharp해짐 → 높은 확률 토큰에 집중
- **T > 1.0**: logit 차이가 축소 → 분포가 flat해짐 → 다양한 토큰 선택 가능
- **T → 0**: 최고 logit 토큰의 확률이 1에 수렴 → greedy decoding과 동일

#### 수치 예시 (Step 1 이후 logits 사용)

Step 1 이후 logits: [2.5, 2.0, 1.5, 1.0, 0.5]

| 토큰 | Logit | T=0.5 (z/0.5→softmax) | T=1.0 (기본) | T=2.0 (z/2.0→softmax) |
|------|-------|----------------------|-------------|----------------------|
| 고양이 | 2.5 | **0.622** | 0.378 | 0.269 |
| 강아지 | 2.0 | 0.230 | 0.229 | 0.222 |
| 토끼 | 1.5 | 0.085 | 0.139 | 0.183 |
| 사자 | 1.0 | 0.031 | 0.084 | 0.151 |
| 쥐 | 0.5 | 0.012 | 0.051 | 0.125 |

관찰:
- **T=0.5**: 고양이에 62.2% 집중. 분포가 매우 날카로움
- **T=1.0**: 고양이 37.8%. 기본 분포
- **T=2.0**: 고양이 26.9%. 분포가 평탄해져서 쥐도 12.5%의 확률을 가짐

#### 정보이론 관점

Temperature는 확률 분포의 **엔트로피(entropy)**를 제어한다:

```
H(P) = -SUM_i P(x_i) * log(P(x_i))
```

- T↓ → 엔트로피↓ → 불확실성↓ → 예측 가능한 출력
- T↑ → 엔트로피↑ → 불확실성↑ → 다양하고 창의적인 출력

이후 예시에서는 **T=1.0**(기본값)을 적용한 확률 분포를 이어서 사용한다:

| 토큰 | 확률 P(x) |
|------|-----------|
| 고양이 | 0.378 |
| 강아지 | 0.229 |
| 토끼 | 0.139 |
| 사자 | 0.084 |
| 쥐 | 0.051 |
| 기타 합산 | 0.119 |

### Step 3: Top-K Filtering

#### 왜 필요한가

어휘 크기가 32,000개 이상인 LLM에서, softmax 후 대부분의 토큰은 극히 낮은 확률(0.001% 이하)을 가진다. 이런 "쓰레기(garbage)" 토큰이 우연히 선택되면 문맥과 무관한 글자가 생성될 수 있다. Top-K는 단순하게 **상위 K개만 후보로 남기는** 방법이다.

#### 동작 메커니즘

1. 확률 기준으로 내림차순 정렬
2. 상위 K개 토큰만 남기고, 나머지는 확률을 0으로 설정
3. 남은 K개의 확률을 합이 1이 되도록 **재정규화(renormalize)**

#### 수치 예시 (K=3)

| 토큰 | 필터 전 P(x) | Top-K 적용 | 재정규화 후 P'(x) |
|------|-------------|-----------|-----------------|
| 고양이 | 0.378 | 유지 | 0.378 / 0.746 = **0.507** |
| 강아지 | 0.229 | 유지 | 0.229 / 0.746 = **0.307** |
| 토끼 | 0.139 | 유지 | 0.139 / 0.746 = **0.186** |
| 사자 | 0.084 | **제거** | 0.000 |
| 쥐 | 0.051 | **제거** | 0.000 |

재정규화 합계: 0.378 + 0.229 + 0.139 = 0.746

#### Top-K의 한계

Top-K는 확률 분포의 **모양(shape)**을 고려하지 않는다:

- 분포가 sharp한 경우 (예: 1위=0.9, 2위=0.05, 3위=0.03): K=3이면 거의 무의미한 2, 3위도 후보에 포함
- 분포가 flat한 경우 (예: 상위 20개가 각 0.04): K=3이면 유효한 후보 17개가 잘려나감

이 한계를 극복하기 위해 Top-P가 등장했다.

---

### Step 4: Top-P (Nucleus Sampling)

#### 왜 필요한가

Top-K가 고정된 개수로 자르는 반면, Top-P는 **확률 분포의 모양에 적응**한다. Holtzman et al. (2020)이 제안한 nucleus sampling은 현재 가장 널리 쓰이는 샘플링 전략이다.

#### 동작 메커니즘

1. 확률 기준 내림차순 정렬
2. 위에서부터 누적 확률을 계산
3. 누적 확률이 `p`를 **처음 초과하는 토큰까지** 포함
4. 나머지 제거 후 재정규화

#### 수치 예시 (P=0.9, Top-K 이후 분포 사용)

Top-K(K=3) 이후 분포: 고양이=0.507, 강아지=0.307, 토끼=0.186

| 토큰 | P'(x) | 누적 확률 | P=0.9 기준 |
|------|-------|----------|-----------|
| 고양이 | 0.507 | 0.507 | 포함 |
| 강아지 | 0.307 | 0.814 | 포함 |
| 토끼 | 0.186 | 1.000 | **0.814 < 0.9이므로 이것도 포함** |

이 경우 P=0.9에서 3개 모두 포함된다 (이미 Top-K로 3개만 남았으므로). 만약 Top-K 없이 전체 분포에서 P=0.9을 적용했다면:

| 토큰 | P(x) | 누적 확률 | P=0.9 기준 |
|------|------|----------|-----------|
| 고양이 | 0.378 | 0.378 | 포함 |
| 강아지 | 0.229 | 0.607 | 포함 |
| 토끼 | 0.139 | 0.746 | 포함 |
| 사자 | 0.084 | 0.830 | 포함 |
| 쥐 | 0.051 | 0.881 | 포함 |
| 기타 일부 | 0.020 | 0.901 | 포함 (p 초과하는 첫 토큰) |
| 나머지 기타 | ... | ... | 제거 |

Top-P의 핵심 장점은 **적응적(adaptive)**이라는 것이다:
- 모델이 확신이 높을 때 (sharp 분포) → 적은 토큰만 포함 → 정확한 출력
- 모델이 불확실할 때 (flat 분포) → 많은 토큰 포함 → 다양한 출력

---

### Step 5: Min-P Filtering

#### 왜 필요한가

Top-P에도 약점이 있다. 분포가 매우 flat하면 누적 확률 p에 도달하기 위해 **수백 개의 저확률 토큰**이 포함될 수 있다. Min-P는 "최고 확률 토큰 대비 너무 낮은 확률의 토큰은 아예 제거"하는 방식으로 이를 보완한다.

#### 동작 메커니즘

```
threshold = max(P(x)) * min_p
P(x_i) < threshold 인 토큰은 제거
```

#### 수치 예시 (min_p=0.1)

현재 남은 후보 (Top-K + Top-P 이후): 고양이=0.507, 강아지=0.307, 토끼=0.186

```
threshold = 0.507 * 0.1 = 0.0507
```

| 토큰 | P'(x) | threshold(0.0507) 비교 | 결과 |
|------|-------|----------------------|------|
| 고양이 | 0.507 | 0.507 > 0.0507 | 유지 |
| 강아지 | 0.307 | 0.307 > 0.0507 | 유지 |
| 토끼 | 0.186 | 0.186 > 0.0507 | 유지 |

이 예시에서는 3개 모두 유지된다. 하지만 만약 Top-K를 크게 설정(K=100)하고 Top-P=0.95로 느슨하게 설정했을 때, 확률 0.001짜리 토큰들이 포함되어 있다면 min_p=0.1이 이들을 효과적으로 제거한다.

Min-P는 비교적 최근에 제안되어(2023) **vLLM, llama.cpp** 등에서 지원하며, OpenAI 공식 API에서는 아직 지원하지 않는다.

---

### Step 6: 최종 Sampling

모든 필터링이 끝나면 남은 후보 토큰들의 확률을 재정규화하고, **확률에 비례하여 랜덤으로 하나를 선택**한다.

#### Multinomial Sampling

```python
# PyTorch 구현 예시
import torch

probs = torch.tensor([0.507, 0.307, 0.186])  # 재정규화된 확률
selected = torch.multinomial(probs, num_samples=1)
# 50.7% 확률로 고양이, 30.7% 확률로 강아지, 18.6% 확률로 토끼
```

#### seed와 재현성

- `seed` 파라미터를 고정하면 동일 입력에 대해 동일한 랜덤 시퀀스가 생성됨
- 디버깅, 실험 재현, A/B 테스트에 유용
- 단, 모든 서버가 완벽한 재현성을 보장하지는 않음 (부동소수점 연산 차이 등)

## 4. Greedy Decoding vs Sampling

### Greedy Decoding

항상 확률이 가장 높은 토큰을 선택한다.

```
x_t = argmax P(x | x_1, ..., x_{t-1})
```

동등한 파라미터 설정:
- `temperature = 0`
- 또는 `top_k = 1`

장점: 결정적(deterministic), 빠름, 사실 기반 답변에 적합
단점: 반복적이고 단조로운 텍스트, 전역 최적이 아닐 수 있음

### Beam Search

여러 후보 시퀀스(beam)를 동시에 탐색하여 전체 시퀀스의 확률이 가장 높은 것을 선택한다.

```
beam_width = 5이면, 매 스텝 상위 5개 시퀀스를 유지하며 확장
```

- 번역, 요약 등 **정확성이 중요한 태스크**에서 사용
- 일반 대화형 생성에서는 잘 쓰이지 않음 (다양성 부족)
- OpenAI API에서는 `n` 파라미터와 `best_of`가 유사한 역할

### Sampling 기반 생성

확률 분포에서 랜덤 샘플링하여 토큰을 선택한다.

장점: 다양하고 자연스러운 텍스트, 창의적 생성에 적합
단점: 비결정적, 간혹 비문이나 엉뚱한 토큰 생성

### 비교 요약

| 전략 | 다양성 | 품질 일관성 | 속도 | 주 용도 |
|------|--------|-----------|------|---------|
| Greedy | 낮음 | 높음 | 빠름 | 코드 생성, 수학, 분류 |
| Beam Search | 낮음 | 높음 | 느림 | 번역, 요약 |
| Top-K Sampling | 중간 | 중간 | 빠름 | 일반 대화 |
| Top-P Sampling | 중~높음 | 중~높음 | 빠름 | 대화, 글쓰기 |
| Top-P + Min-P | 중~높음 | 높음 | 빠름 | Open LLM 서빙 |

## 5. 실용 가이드

### 용도별 추천 파라미터 조합

| 용도 | temperature | top_p | top_k | repetition_penalty | min_p |
|------|-------------|-------|-------|-------------------|-------|
| 코드 생성 | 0 | - | - | - | - |
| 수학/논리 추론 | 0 | - | - | - | - |
| 사실 기반 QA | 0.1~0.3 | 0.9 | - | - | - |
| 일반 대화 | 0.7 | 0.9 | - | 1.0~1.1 | - |
| 창의적 글쓰기 | 0.8~1.0 | 0.95 | - | 1.1~1.2 | - |
| Open LLM 범용 | 0.7 | 0.9 | 50 | 1.1 | 0.05 |
| 브레인스토밍 | 1.0~1.5 | 0.95 | - | 1.2 | - |

> `-`는 비활성화 또는 기본값 사용을 의미

### 안티패턴 (피해야 할 조합)

**1. temperature와 top_p를 동시에 극단적으로 설정**
```
temperature=2.0 + top_p=0.99  → 거의 랜덤한 출력, 품질 급락
```

**2. 높은 temperature + 높은 repetition_penalty**
```
temperature=1.5 + repetition_penalty=1.5  → 반복 억제가 과도하여 비문 생성
```

**3. 극단적으로 낮은 top_k**
```
top_k=2  → 사실상 이분 선택, 다양성 거의 없음
```

**4. top_p=1.0 + top_k=-1 + temperature > 1.0**
```
필터링 없이 높은 temperature → 쓰레기 토큰 선택 확률 증가
```
